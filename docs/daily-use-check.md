# 实际写作检查

适用：0.77.3 本地候选。当前状态：用户选择稍后体验；以下是待执行步骤，不是通过记录。
历史版本已通过的输入法/基础旁白检查不被覆盖，也不自动升级为本轮验收。

## 一次 20–30 分钟的写作

准备一份可丢弃的文章副本，包含标题、普通段落、粗体/斜体、一个列表、一个引用和一个表格。
从已安装的 Markdown 打开它，按平时速度写作；不必刻意把每个功能逐个点一遍。

1. 使用平时的中文输入法写几段话，提交一次候选、取消一次候选。在加粗/斜体文字末尾按空格，
   再输入几个词。预期：不吞空格、不丢字、不重复；候选未结束时不会被保存或切换强制提交。
2. 写作期间做几次撤销/重做、正文与源码切换，再保存。试着读和改文章中后部，注意光标、滚动
   和按键响应。预期：内容与位置符合操作；若明显停顿，记录大致文档长度、位置及操作。
3. 结束时核对文件保存和草稿备份状态，正常退出并重开；检查文件末尾和最后几处修改。
   预期：已保存文件和已确认草稿分别保持正确内容；草稿恢复不自动取得旧文件的保存授权。

完成后只需回复：实际时长、输入法、是否丢字/卡顿/内容不一致；没做的注明未测。

## 旁白补充（有空时）

通过系统「辅助功能」里的「旁白」开启 VoiceOver，或使用系统启用快捷键。
在临时文章中定位一个标题和一个表格单元格，再用键盘打开源码/设置并返回。
预期：听到对应名称/内容，焦点返回合理位置，备份通知不会反复打断。
请注明实际听到的异常；自动可访问性树检查不等于听过旁白。

开发者保存自动化记录时必须分别注明：受控输入、实际输入法、可访问性语义、实际听觉体验、
受控持续运行和真人持续写作。未测项目保留未测，不要求为了提交而把它们改成通过。
