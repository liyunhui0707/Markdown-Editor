# 四阶段写作质量改进

用户授权：2026-11-18，依次完成四阶段；本机测试，全面采用 TDD 和既有 Git 管理。
起点为干净检查点 `a49c49b`；已发布 0.81.0 的文件和标签不改写。

1. **稳定、安静的写作。** 先保留/复现近容量原速失败，测量解析、投影与确认成本；
   修复瓶颈，不放慢原速测试、不增大 64 项队列、不削弱完整 PM/main 校验。
   标题不随 IME 候选闪烁；正常保存状态集中展示，受保护编辑给出简短的源码入口。
   保存失败、冲突和未知结果仍明显可见。失败测试必须留下证据并有界退出其合成进程。
2. **常用 Markdown 的准确展示。** 分隔线、转义/实体、自动/引用式链接及混合引用
   应语义展示；缺少精确映射的区域保持只读并可通过源码修改。HTML 不执行，远程资源
   不自动读取，数学/Mermaid 扩展不因源码保留而宣称支持。验证原始字节、邻接编辑和恢复。
3. **连续创作。** 补齐普通段落与标题之间的选中替换、粘贴和边界续写；成组验证既有
   列表/引用退出、表格前后续写、格式、撤销重做、源码、保存和重开。跨父级复杂结构
   不通过泛化序列化或取消保护来实现。每项新行为先有失败测试，再增加实现。
4. **交付。** 收拢 CLI/MCP，与真实 stdio 客户端验证创建、打开和失败回执；同步安装、
   使用、更新说明，完成完整适用 CI、固定候选包及本机安装检查，再合并和发布。
   保留回退材料，只注册实际安装 App。用户已选定 **Markora**：统一应用、图标、命令、
   文档和仓库名称；保留旧数据身份与命令兼容，付费签名/公证仍暂缓。
   其他文件系统/同步服务和图片格式按具体需求独立验证，不因本计划自动开放未知位置。

每阶段具有实现和验收检查点；完整功能组使用短分支/PR，不按按钮拆阶段。
现有 CLI/MCP 提交已独立备份，随依赖它的质量组在完整 CI 通过后整合。
失败记录不被后续通过覆盖。真实 IME、听读和真人持续写作未测时如实记录；
用户体验不再是发布等待门槛。实际安装替换前确认正常退出，GUI 测试使用独立合成资料。

计划自审：接受以上边界。性能修复必须有对照测量，语义只读展示与可编辑映射分离；
新增跨块编辑保留完整预期投影和精确逆操作。不得把四阶段解释成全部 Markdown
扩展、所有存储位置或无限容量支持。架构、原生保存、源字节和已接受视觉基线保持。
