# 文档全流程复盘与本轮验收依据

基线：`26b6520` / 0.80.1。候选：0.81.0，PR #175。
用户批准依次完成文档流程、输入协调与长文、视觉及交付三个功能组。
本记录区分已实现、自动化证据、真实使用验收；未通过的检查不记作完成。

## 主要结论

原界面已经有稳定的视觉基线，但文档操作仍带有实验阶段的语义：
新建之后只有“另存新文件”，创建文件后仍像独立草稿；首次保存堆叠确认；
关闭不能直接保存；源码应用与文件保存关系不直观。
因此，本轮先统一文档的保存目标和状态，再简化交互，不继续逐个增加按钮。

输入时变灰有明确原因：旧界面将每个尚待主进程确认的字符，以及中文候选状态，
都映射为整个工作区不可操作。保护输入的目的合理，但短暂确认也触发闪动，
既像异常，又迫使用户等待。现在把“操作意图”和“允许真正执行”分开：
普通确认期间保留入口，一次明确操作限时等待；候选输入不强制提交、取消或切换。
历史操作、未知结果、恢复中的输入和长期文件操作仍有可见限制。

## 文档操作契约

| 操作 | 本轮行为 | 必须核实的结果 |
|---|---|---|
| 新建 | 增加未命名草稿，保留其他文档 | 可立即写作，不先弹保存面板 |
| 第一次保存 | 一个原生位置面板 | 文件名、当前保存目标、底栏一同更新 |
| 修改后保存 / ⌘S | 写回当前目标 | 成功状态只在确认后出现；重开内容一致 |
| 另存为 | 用新名称创建文件，并切换当前目标 | 后续保存仅更新新文件；原文件不变 |
| 导出副本 | 创建 Markdown 及附件副本 | 当前目标、未保存状态和撤销历史不变 |
| 源码 ⌘S | 确认应用源码后保存同一文档 | 应用失败或未知时不得继续写文件 |
| 源码“应用并返回” / ⌘Enter | 只应用到正文 | 文案明确仍需保存文件 |
| 关闭已保存文档或新建空文档 | 新鲜核对后安静关闭 | 磁盘变更或未知结果不被当成已保存 |
| 关闭未保存文档 | 保存、保留草稿并关闭、取消 | 保存取消或失败时保持文档打开 |
| 关闭窗口 / 退出 | 依次走同一文档关闭流程 | 不绕过源码、候选、写入和备份保护 |

“保存”不是自动保存原文件；本地草稿备份也不是磁盘文件保存。
导出目前指 Markdown 副本，不代表已经提供 PDF、Word 或 HTML 导出。
另存不会覆盖已有同名目标，这是当前新文件写入器的明确边界。

## 界面处理

保留当前米白与绿色、侧栏、正文、工具栏和底栏布局。只保留一个主要“保存”入口；
另存和导出收进文档操作菜单。普通保存成功由底栏表达，避免成功回执持续挤压正文；
导出回执和重开 / Finder 定位缩成一行。失败和未知结果保留明显提示及恢复入口。
后台目录列表刷新与关闭的重叠应限时等待，不能让用户一次关闭请求无声失效。

正常和较窄窗口都要检查真实截图、正文空间、菜单遮挡和键盘返回焦点。
DOM 可点击不等于视觉通过，合成 composition 也不等于中文输入法通过。

## 平台规范参照与差异

核对日期：2026-11-17。Apple 的 [菜单栏指南](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar)
定义了熟悉的文件菜单和快捷键、新文档首次命名选位置、保存当前文档以及关闭文档的关系。
本轮按这些基本关系组织交互。[文件管理指南](https://developer.apple.com/design/human-interface-guidelines/file-management)
支持用合适的保存界面帮助用户选择位置。

这不是对原生 NSDocument 行为的完整实现：未启用原文件自动保存；Apple 更偏好
Duplicate，本应用保留用户已批准的“另存为 / 导出副本”，并明确两者的目标关系。
受验证的本地 APFS / OneDrive 保存策略、容量和复杂结构编辑边界继续存在。
不能据此声称支持任意位置、任意 Markdown 或正式签名分发。

## 扩大 CI 后的混合长文压力结果

验收过程记录：CI 108 暴露了旧测试关闭选择、变量作用域和满容量备份处理的差异；
CI 110 的三项修正通过，另有原生选区测试驱动缺少明确焦点/点击选区同步。
CI 111 的选区驱动修正通过，但约 15 万字混合文章的列表连续输入触发队列饱和。
该次结果属于性能验收失败，不能作为偶发错误重跑到绿，也不改慢输入或增加队列。

Node 组件采样显示，列表/引用范围校验中对完整树做规范化复制及 JSON 字符串比较有额外开销。
本轮定向优化在两个容器编辑规划器中逐项比较完整规范化语义树，只合并相邻相同标记文本；
不缓存可变投影，不略过其他节点/属性，不更改解析、PM before/after 和独立主进程证明。
差异矩阵与冻结输入测试核对旧规范化 JSON 语义。组件耗时观察不能代替真实窗口吞吐验收；
规范化比较修正的全量 Node 检查为 3,704 通过、2 项既有跳过；111 个候选运行文件与源码一致。
完整 CI、原速长文和实际安装必须通过后才交付，最终结果以 PR #175 和本地交付记录为准。
原始失败现场与测量保留在本轮私有证据目录。
