# CLI、MCP 与格式显示检查 — 2026-11-18

本组在现有 0.81.0 App 之外建立本地伴侣工具：状态、明确文件打开、独占创建后显示。
共用系统的原生打开链路，没有增加编辑器内部路径 IPC、HTTP 服务或写回授权。
名字选择由用户延后，应用名称、bundle ID 与用户数据位置保持现状。

## 截图中的界面

- “输入待确认”来自文件状态展示，包含输入法预编辑、待确认修改等状态。内部仍需区分，
  但无需在标题栏反复切换。更合适的是稳定标题、一个未保存标识和低干扰的输入状态。
- “修改未保存”表示文件当前正文尚未写回，不等于本地草稿没有备份。
  应保留可见标识；不要求在标题、侧栏、底栏重复显示同一段话。
- Services 是标准 macOS 服务菜单。App 使用 Electron 的 `appMenu` role，
  性能分析服务由本机其他应用提供，不能据此判断这个 App 处于开发模式。
- 黄色提示对应 `unsafe-source-range` / `unsafe-format-range`，表示那次可视化修改被拒绝。
  原文被保留，不代表整份文件不可用，也不能仅凭截图确认具体触发操作。
  后续应缩短措辞、给出明确的源码入口与就地反馈，不以隐藏真正的失败冒充支持。

本组回答和记录这些现象，没有将它们与 CLI 混成一次未经验证的 UI 或编辑器重写。

## 格式文档

样本为 [format-boundaries.md](../../examples/format-boundaries.md)，仅含合成内容。
实际用户副本在 Inbox 中独占创建，已通过已安装 App 打开；可见首屏显示正确的标题层级与正文。
投影检查覆盖六级标题、行内格式、列表、任务、表格、代码块、硬换行、图片引用与扩展边界。

当前观察：

| 分类 | 结果 |
| --- | --- |
| 标题、常见粗斜体与行内代码、列表、基本围栏、矩形表格、硬换行 | 进入对应 Document 显示结构；首屏标题/正文已实际查看 |
| 分隔线、含转义/实体的段落、自动 URL、部分混合/嵌套引用 | 当前回退为受保护源码块，不能记为完整可视化格式支持 |
| 脚注、引用式链接、HTML | 保留原始源码，未作为完整可视化编辑能力 |
| Mermaid / 数学扩展 | 未承诺图形/公式渲染；不能因源码保留就报通过 |
| 远程图片 | 保留引用，预期不自动联网；本组未授予网络图片加载能力 |

结论：格式检查**没有全部通过**。这里同时包含正常显示案例和明确的产品缺口；
不是将现状复制成“所有格式通过”的测试。后续应将只读语义呈现与可视化可编辑范围分别改进。

## 验证与边界

独立伴侣 0.1.0 已通过单元、协议和安装副本检查；本机实际 stdio 自测发现三项工具，
查询到 App 0.81.0，验证拒绝覆盖现有合成文件并提交原生打开请求。
标准 CLI 的打开回执不宣称已显示或保存。Codex 中新增 `markdown-editor` 配置，
当前会话尚未加载新工具；不能把配置成功写成当前模型已经调用了新 MCP 工具。

已发布 App、安装包和版本号未修改。既有近容量原速输入失败仍保留，未因本组工具测试
通过而关闭；全量 App CI 与真人输入/旁白结果不得被这些定向检查替代。
