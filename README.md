# Markdown

一个本地 macOS Markdown 编辑器：从 Finder 打开文件，在简洁的正文界面写作，
使用源码模式处理完整 Markdown，明确保存，并保留本地草稿和保存版本。
不需要账号、Vault 或托管服务。

当前源码版本为 **0.77.2 本地开发候选**。已实现日常文件编辑流程，仍在进行稳定性验收；
尚未提供经过 Developer ID 签名、公证的正式公开版本。

## 开始使用

打开已安装的 `Markdown.app`，以后可从 Dock 启动，无需进入工程目录或运行终端命令。
安装与更新步骤见[安装、更新与回退](docs/install.md)。

1. 点「新建」写草稿，或点「打开…」选择 `.md` 文件。Finder 的「打开方式」也支持 Markdown。
2. 普通文件直接进入独立的编辑缓冲区。输入不会立即改写原文件；保存时才写回绑定目标。
   只读检查视图和无法建立安全保存绑定的文件仍保持只读，可创建编辑副本。
3. 点击「保存」或按 `⌘S` 写回绑定文件，首次保存需确认并保留旧版本。
   「另存新文件…」创建新的 `.md`，绝不覆盖已有目标；继续修改不会自动更新这份导出文件。
4. 需要完整 Markdown 时打开「源码」，编辑后「应用并返回」，再按需要保存到文件。
   源码窗口里的 `⌘S` / `⌘Enter` 只应用源码修改。

`.md` 默认打开方式由你决定。需要更改时，在 Finder 的文件「显示简介」中选择 Markdown，
再选择「全部更改」。开发安装流程不自动抢占默认关联。

## 写作与文档操作

| 能力 | 当前范围 |
| --- | --- |
| 正文创作 | 普通段落、六级标题、常见粗体/斜体/行内代码及组合、链接创建与地址编辑 |
| 列表和引用 | 任务项、六层以内列表、单层引用；支持明确缩进/前缀的多行段落和同级选中替换、粘贴、拆分合并 |
| 代码和表格 | 基本闭合围栏代码块；最多 8 列、32 行的矩形管道表格及常见单元格格式 |
| 图片 | 显式选择或粘贴 PNG/JPEG；托管附件随另存文件导出，移动文档时请一起移动附件 |
| 查找与导航 | 文档查找/替换、标题大纲、已打开文档筛选、最近文档 |
| 阅读与键盘 | 明暗主题、阅读设置、工具栏键盘导航、命名控件和焦点提示 |
| 源码 | 草稿可编辑完整 Markdown，有独立撤销/重做；应用后进入正文历史与草稿备份 |

在普通段落开头输入 `#` 后按空格可创建一级标题；也可使用工具栏选择标题。
支持的列表/引用内，Enter 创建下一项/段，Backspace 合并；引用或代码块可用 `⌘Enter`
回到正文。复杂结构不能直接编辑时，原文保留，可切换源码处理。

0.77.1 修复格式边界的空格被拒绝：普通正文、标题、列表、引用和表格中的受支持位置，
加粗/斜体末尾的分词空格可以回到适当的外层格式，再继续输入。
若空格恰好碰到源码换行，仅在必要时将相邻软换行变为其可见空格，或将两空格硬换行改用
反斜杠写法；显示内容和硬换行含义不变，撤销恢复原始字节，其余源码不被整体重排。

0.77.2 优化长混合文章中含链接段落、列表和引用的连续输入，减少重复整篇解析。
只复用通过原文与上下文检查的块；无法确认时仍完整解析，不改变保存和恢复规则。

## 保存、备份与恢复

**本地草稿备份与文件保存是两件事。** 底部会分别显示状态。备份保存最近已确认正文，
不保证保留尚未提交的输入法候选、未应用的源码修改、旧撤销历史或保存授权。
退出重开后，从「草稿」恢复为独立副本；必要时重新选择文件或另存新文件。

文件保存支持通过检查、归你所有且未同步的普通本地 APFS 位置，包括符合检查的桌面、文稿、
下载、主目录之外的目录和外接 APFS 卷。打开文件不等于取得任意位置的保存许可。
网络卷、非 APFS、同步目录、符号链接路径及不支持的所有权/权限仍会拒绝。

文件被外部修改、替换或移走时，保存会暂停。可以核对当前内容与磁盘版，保留当前写作另存，
或经重新核对打开独立的磁盘编辑版本。不会自动合并或静默覆盖。
保存版本、草稿达到容量时，使用 App 的恢复/归档流程；不要手动删除未知恢复记录。

## 当前限制与验收状态

- 文档最多 524,288 个 UTF-16 单位 / 2 MiB。每份文档最多 16 张托管图片；
  每张最多 4 MiB，附件总量、像素和会话也有边界。接近容量不等于保证交互流畅。
- 多段落列表项、懒续行、嵌套引用、部分复杂 Markdown 和跨结构编辑仍可能要求源码模式。
  表格跨单元格区域粘贴、任意外部图片格式和远程资源加载不属于当前能力。
- 输入法候选期间，切换、格式操作和保存会受到保护。跨行/跨格式的输入法预编辑仍有约束。
- 自动化已经覆盖受控输入、保存冲突、恢复和长文循环；实际中文输入、旁白及较长真实写作
  的结论按版本和场景记录，不能由自动化替代。当前真人持续写作仍待完成。
- 长混合文章的逐键延迟仍需优化；较长自动化运行和有限内存样本不能证明所有场景长期稳定。

本轮性能证据与测量边界见[长文输入优化记录](docs/audits/2026-11-15-mixed-input-performance.md)。

## 开发与验证

仓库使用 Node **24.20.0**（mise 锁定），Electron 使用自己的运行时。
从 `apps/desktop/` 执行，先阅读 [DEVELOPMENT.md](DEVELOPMENT.md) 与 [AGENTS.md](AGENTS.md)：

```sh
mise exec -- npm ci           # 仅新检出；替换 node_modules
mise exec -- npm run dev      # 当前 Document App
mise exec -- npm run test:ci  # Node 测试与基线门槛
mise exec -- npm run audit:prod
mise exec -- npm run audit:full
mise exec -- npm run pack     # 本地未签名 App，不等于正式发布
```

修改 `lib/document-demo-entry.js` 后必须重建对应 Document bundle，并核对产物与源码一致。
GUI、合成 APFS 卷及真实输入测试的前提与操作范围见[开发说明](DEVELOPMENT.md)。
开发产物与恢复材料放在忽略的 `.local/`，不进入安装包；不运行清扫来删除历史证据。

历史 Vault/CM6、AI 和插件说明保留在[历史 README](docs/history/readme-through-0.77.0.md)，
不属于当前安装 App 的产品功能。分阶段记录见[Stage History](docs/stage-history.md)。
