# Markora

一个本地 macOS Markdown 编辑器：从 Finder 打开文件，在简洁的正文界面写作，
使用源码模式处理完整 Markdown，明确保存，并保留本地草稿和保存版本。
不需要账号、Vault 或托管服务。

当前版本为 **0.82.0**；发行状态、安装包及适用验收结果以
[GitHub Releases](https://github.com/liyunhui0707/Markora/releases) 为准。
当前支持 Apple Silicon / arm64。本轮构建采用 ad-hoc 签名，未进行 Developer ID 签名和公证。

## 开始使用

打开已安装的 `Markora.app`，以后可从 Dock 启动，无需进入工程目录或运行终端命令。
安装与更新步骤见[安装、更新与回退](docs/install.md)。

1. 点「新建」写草稿，或点「打开…」选择 `.md` 文件。Finder 的「打开方式」也支持 Markora。
2. 普通文件直接进入独立的编辑缓冲区。输入不会立即改写原文件；保存时才写回绑定目标。
   只读检查视图和无法建立安全保存绑定的文件仍保持只读，可创建编辑副本。
3. 点击「保存」或按 `⌘S` 保存当前文档；未命名草稿直接选择名称和位置。
   「更多文档操作」中的「另存为…」创建新 `.md` 并切换保存目标；「导出副本…」保持当前目标不变。
   新文件不会覆盖已有目标。普通本地保存不再重复确认；OneDrive 仍提示恢复材料与同步边界。
4. 需要完整 Markdown 时打开「源码」，编辑后「应用并返回」，再按需要保存到文件。
   源码窗口里的 `⌘S` 会应用并保存当前文档；`⌘Enter` 和「应用并返回」仅应用到正文。

`.md` 默认打开方式由你决定。需要更改时，在 Finder 的文件「显示简介」中选择 Markora，
再选择「全部更改」。开发安装流程不自动抢占默认关联。

需要由 AI 生成后立即打开文件，可使用独立的 [Markora CLI / MCP 伴侣](integrations/markora/README.md)：
提供状态查询、打开明确文件、独占生成新 Markdown 并提交打开请求。
伴侣需要 Node 24+，单独安装；图形 App 本身仍不需要 Node。
`markora` 是主命令，旧的 `mdapp` 入口在本机升级时保留兼容。
格式检查样本见 [Markdown 格式边界测试](examples/format-boundaries.md)，实际支持与缺口见
[检查记录](docs/audits/2026-11-18-cli-mcp-format-review.md)。

## 写作与文档操作

| 能力 | 当前范围 |
| --- | --- |
| 正文创作 | 普通段落与标题之间的选中替换和多段粘贴、六级标题、常见粗体/斜体/行内代码及组合、链接创建与地址编辑 |
| 列表和引用 | 任务项、六层以内列表与明确前缀引用；列表项可含多个段落，支持同项/同级引用段落的选中替换、粘贴、拆分合并和整项缩进 |
| 代码和表格 | 基本闭合围栏代码块；最多 8 列、32 行的矩形管道表格及常见单元格格式 |
| 图片 | 显式选择、粘贴或拖入 PNG/JPEG；已有相对引用可收集同目录/子目录图片，再应用为托管附件；附件随保存/另存导出，移动文档时请一起移动附件 |
| 查找与导航 | 文档查找/替换、标题大纲、已打开文档筛选、最近文档 |
| 阅读与键盘 | 明暗主题、阅读设置、工具栏键盘导航、命名控件和焦点提示 |
| 源码 | 草稿可编辑完整 Markdown，有独立撤销/重做；应用后进入正文历史与草稿备份 |

在普通段落开头输入 `#` 后按空格可创建一级标题；也可使用工具栏选择标题。
支持的列表/引用内，Enter 创建下一项/段，Backspace 合并；引用或代码块可用 `⌘Enter`
回到正文。复杂结构不能直接编辑时，原文保留，可切换源码处理。

列表内用 `⌘Enter` 在文字后另起同一项内的段落；普通 Enter 仍创建下一项。
Tab / Shift+Tab 移动整项及其段落、子列表。嵌套引用内的 Enter/Backspace 在当前层分段、合并；
选择「引用」可增加一层，选择「正文」可把内层段落提升一层。跨层选区仍受保护。

分隔线、转义/实体、自动与引用式链接以及混合引用可以语义预览；缺少精确映射的区域
通过源码编辑。预览中的链接不自动导航，HTML 保留为源码；Mermaid 和数学扩展仍未提供图形渲染。

0.77.1 修复格式边界的空格被拒绝：普通正文、标题、列表、引用和表格中的受支持位置，
加粗/斜体末尾的分词空格可以回到适当的外层格式，再继续输入。
若空格恰好碰到源码换行，仅在必要时将相邻软换行变为其可见空格，或将两空格硬换行改用
反斜杠写法；显示内容和硬换行含义不变，撤销恢复原始字节，其余源码不被整体重排。

0.77.2 优化长混合文章中含链接段落、列表和引用的连续输入，减少重复整篇解析。
只复用通过原文与上下文检查的块；无法确认时仍完整解析，不改变保存和恢复规则。

0.77.3 进一步减少单次编辑中的重复文档投影和整篇复制，保留完整内容校验。
各次投影仍相互独立，中文输入、历史和文件保存规则保持不变。

0.77.4 继续优化长文输入：提前识别无法保持原格式的强调末尾空格写法，仍完整校验回退结果；
减少不可变解析树的重复遍历，并为通过检查的短单行段落减少末尾空格的整篇重解析。
普通空格、代码内空格、历史、保存及队列保护保持原有规则。

## 保存、备份与恢复

已保存且磁盘核对一致的文件、空白新草稿可直接关闭。未保存内容提供「保存」「保留草稿并关闭」和「取消」；保存取消或失败时继续保留窗口。关闭整个窗口按相同规则逐份处理，不会静默保存或丢弃未应用源码、候选输入和未知结果。

0.80.1 修复部分普通文件确认后仍未写回的问题；保存失败提示会在当前滚动视口保留，
不会因位于文末而看不到。保存后应显示「正文已保存」；草稿备份仍与文件写入分别确认。

**本地草稿备份与文件保存是两件事。** 底部会分别显示状态。备份保存最近已确认正文，
不保证保留尚未提交的输入法候选、未应用的源码修改、旧撤销历史或保存授权。
退出重开后，从「草稿」恢复为独立副本；必要时重新选择文件或另存新文件。

文件保存支持通过检查、归你所有且未同步的普通本地 APFS 位置，包括符合检查的桌面、文稿、
下载、主目录之外的目录和外接 APFS 卷。打开文件不等于取得任意位置的保存许可。
另支持通过检查、已下载到本机的 OneDrive 文件：位置须在当前用户的
`Library/CloudStorage/OneDrive-*` 中，位于主目录所在的本地 APFS 设备；原生选择器中的
`~/OneDrive` 入口会解析到该位置。可保存、带托管图片另存新文件，并保留冲突保护。
仅确认本机文件已写入，是否上传完成请查看 OneDrive。

OneDrive 保存会在目标目录保留隐藏恢复区，其中旧正文可能同步到云端；首次保存会提示。
本机应用私有目录也独立保留完整旧正文和当前正文。恢复区不会自动清理或自动回写。
尚未下载、存储元数据不受支持的文件会拒绝；请先在 Finder/OneDrive 中确认本地可用。
网络卷、非 APFS、其他同步目录、任意符号链接路径及不支持的所有权/权限仍会拒绝。

文件被外部修改、替换或移走时，保存会暂停。可以核对当前内容与磁盘版，保留当前写作另存，
或经重新核对打开独立的磁盘编辑版本。不会自动合并或静默覆盖。
保存版本、草稿达到容量时，使用 App 的恢复/归档流程；不要手动删除未知恢复记录。

## 当前限制与验收状态

- 文档最多 524,288 个 UTF-16 单位 / 2 MiB。每份文档最多 16 张托管图片；
  每张最多 4 MiB，附件总量、像素和会话也有边界。接近容量不等于保证交互流畅。
- 懒续行、引用内混合列表/代码等子块、部分复杂 Markdown 和跨结构编辑仍可能要求源码模式。
  表格跨单元格区域粘贴、任意外部图片格式和远程资源加载不属于当前能力。
- 容器创作限六层、32 个段落/项目与既有 4096 单位单次补丁。无法保持 CommonMark 结构的
  空段操作会拒绝；列表项最前面的空段加后续文字不被静默改成两个不同结构。
- 新建、保存、另存和切换会等待已有输入确认；候选尚未提交时提示先完成选词，不强行提交或事后自动执行。格式操作仍受保护。跨行/跨格式的输入法预编辑仍有约束。
- 自动化已经覆盖受控输入、保存冲突、恢复和长文循环；实际中文输入、旁白及较长真实写作
  的结论按版本和场景记录，不能由自动化替代。真人持续写作的版本、环境与结果在发行记录中分别列明。
- 长混合文章的逐键延迟仍需优化；较长自动化运行和有限内存样本不能证明所有场景长期稳定。
  接近容量上限时，快速连续输入仍可能达到确认队列上限并暂停，需核对保留内容后明确恢复。

最新性能证据与测量边界见[首键与长文输入记录](docs/audits/2026-11-16-long-document-input.md)，
前一轮见[编辑响应记录](docs/audits/2026-11-16-writing-response.md)。

见[稳定候选验收记录](docs/audits/2026-11-15-local-stable-candidate.md)、
